# Feature 0056: Settings → Documents tab (draft docs from docs/, preview, role & email mapping)

## Context

Add a **Documents** tab in the Settings page subsubheader (same row as Price Scraping, Exchange Rate, Mail Settings, AI Agent) at `http://localhost:5173/settings`. The tab is **admin-only** (Settings is already protected by `AdminRoute`). In this tab, display **all draft documentation from the repo’s `docs/` folder**, with for each document: **presentation** (title, path, optional description), **PDF preview** (for PDF files; for Markdown, use rendered markdown or link), and **role** plus **when it is attached to an email template**.

No product-manager sections (no success criteria, timeline, migration). No mock/demo data — use real data from backend and `docs/` (or manifest).

### Backend

- **`backend/app/api/v1/admin.py`**
  - New endpoints (admin-only, same dependency as other admin settings):
    - **`GET /api/v1/admin/settings/documents/list`**  
      Returns list of “draft” documentation entries from `docs/`. Each item: `path` (relative to repo root or `docs/`), `name`, `type` (`md` | `pdf` | other). Optionally include `role` and `email_templates[]` when provided by manifest (see below).
    - **`GET /api/v1/admin/settings/documents/preview`**  
      Query param: `path` (relative path under `docs/`). Response: for `.pdf` return file bytes with `Content-Disposition: inline` and `Content-Type: application/pdf`; for `.md` return text/plain or raw content so frontend can render markdown. Restrict to `docs/` only (no path traversal).

- **Manifest for role and email template**
  - **Option A (recommended):** Add a small manifest file under `docs/` (e.g. `docs/documents_manifest.yaml` or `docs/_documents_manifest.yaml`) that maps document path (relative to `docs/`) to optional `role` and `email_templates` (list of template names, e.g. `account_approved.html`, `deposit_announced.html`). Backend reads this when building the list and attaches `role` and `email_templates` to each entry; if a path is not in the manifest, return `role: null`, `email_templates: []` (frontend shows "—").
  - **Option B:** Hardcode in backend a mapping for known docs (e.g. `DOCUMENT_EMAIL_MAPPING.md` → describes account_approved / deposit_announced; no attachment). Prefer Option A for flexibility.

- **Listing `docs/`**
  - Backend must list files under `docs/` (or a configurable path, e.g. `DOCS_PATH` defaulting to project root `docs/`). Restrict to a single directory (and optionally one level of subdirs, e.g. `docs/` and `docs/features/`, `docs/commands/`) to keep the list manageable. Filter by extension: `.md`, `.pdf`, and optionally `.html` if desired. No path traversal; resolve all paths to a canonical subpath of `docs/`.

## Algorithm / behaviour

1. **List endpoint**
   - Resolve base path to repo `docs/` (or env `DOCS_PATH`).
   - Walk only allowed subpaths (e.g. `docs/` and `docs/**` one or two levels). For each file with extension in `[.md, .pdf]` (and optionally `.html`), add an entry with `path` (relative to `docs/`), `name` (filename or derived title), `type` (e.g. `md`, `pdf`).
   - If manifest exists, parse it and for each list entry whose path matches a manifest key, set `role` and `email_templates` from the manifest; otherwise leave null/empty.
   - Return JSON array.

2. **Preview endpoint**
   - Accept `path` as query parameter (e.g. `docs/features/0056_PLAN.md` or `features/0056_PLAN.md` relative to `docs/`).
   - Normalize and validate: ensure resolved path is under `docs/` (no `..`, no absolute). If invalid, return 400.
   - If file is PDF: open as binary, return with `Content-Type: application/pdf` and `Content-Disposition: inline`.
   - If file is Markdown (or other text): read as text, return with `Content-Type: text/plain; charset=utf-8` (or allow frontend to request as-is and render markdown).

3. **Frontend**
   - On Documents tab mount, call `getDocumentsList()`. Display one card/row per document with: **presentation** (title from name/path, path, optional description from manifest if present), **role** (or "—"), **email template(s)** (or "—").
   - **Preview:** For `type === 'pdf'`, use an iframe or object URL from `getDocumentPreview(path)` (blob) to show PDF inline or in a modal. For `type === 'md'`, fetch preview content and render with a markdown component (e.g. existing or a simple one; no new dependency if the project already has markdown rendering elsewhere).

## Consistency and style

- **Access:** Only admin; Settings route is already behind `AdminRoute`. No extra backend check needed if the new endpoints are under the same admin router/dependency.
- **UI:** Same subsubheader tab pattern as Price Scraping / Exchange Rate / Mail / AI Agent; same panel/card hierarchy and tokens (e.g. `rounded-xl`, `border border-navy-700`, `bg-navy-800`, labels `text-xs uppercase tracking-wider text-navy-400`, values with semantic color). Table or cards per document; avoid long paragrafs; use badges for role and email template(s).
- **Security:** Backend must restrict list and preview to a fixed `docs/` (or configured) subtree; reject any path that escapes (e.g. `..` or absolute).
