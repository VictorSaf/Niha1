# 0071 – TRODUCER code flow: Login → NDA → code entry → introducer NDA invitation → INTRODUCER

## Context

When a user with role **TRODUCER** shares their referral code, the recipient goes to Login, selects NDA, chooses "I have a code", enters the code, submits their data, and the backend creates an **INTRODUCER** user and sends an email with template **introducer_nda_invitation** with **NDA attached**. The recipient follows the link in the email, sets password, and is redirected to `/introducer/dashboard` (no NDA upload or admin approval).

---

## Flow (verbatim from user)

1. TRODUCER sends code to someone
2. Recipient goes to **Login** → **NDA** → **I have a code**
3. Inserts code, submits data (without NDA on form)
4. Backend creates **INTRODUCER** user and sends email with template **introducer_nda_invitation** with **NDA attached**
5. Recipient follows link in email, sets password
6. Redirected to **/introducer/dashboard** (no NDA upload or admin approval)

## End-to-end flow (technical)

### 1. Code entry on Login

- Login page: mode `nda` → user selects "I have a code" → mode `code-entry`
- User enters 8-char code → `handleValidateCode` → `POST /contact/validate-code`
- Response `{ valid: true, type: "troducer" }` (or `"preintroducer"`) → mode `introducer-form`

### 2. Introducer form submit

- User fills: email, first name, last name, entity (optional), NDA file (optional)
- `handleIntroducerSubmit` → `submitIntroducerNDARequest` with `referral_code`, `position: ""`
- `POST /contact/introducer-nda-request` with FormData

### 3. Backend: INTRODUCER + email (NDA attached)

- `create_introducer_nda_request`: consumes `referral_code`, creates `ContactRequest`
- When `request_flow == "introducer"` and `not nda_file_name` and `referred_by_user_id`:
  - Creates `User` with `role=INTRODUCER`, `nda_signed=True`, `invitation_token`
  - Generates NDA via `get_document_bytes("nda", ...)`
  - Calls `send_introducer_nda_invitation` with `nda_attachments`
- Email template: `introducer_nda_invitation.html` (NDA PDF attached, link `setup_url`)

### 4. User follows link

- Link: `{base_url}/setup-password?token={invitation_token}`
- `SetupPasswordPage`: validates token, user sets password
- User is already INTRODUCER with `nda_signed=True` → redirect to `/introducer/dashboard` (no NDA upload step)

---

## Verification points

1. **LoginPage** – `introducer-form` must send `referral_code` in `submitIntroducerNDARequest` (confirmed: `referralCode.trim()`).
2. **introducer-nda-request** – `position` is required; LoginPage sends `position: ''` (empty string). Backend accepts empty string.
3. **introducer_nda_invitation** – NDA must be attached; `send_introducer_nda_invitation` receives `nda_attachments` from `get_document_bytes("nda", ...)`.
4. **SetupPasswordPage** – PREINTRODUCER with `!ndaSigned` must show NDA upload step (confirmed: lines 96–98).
