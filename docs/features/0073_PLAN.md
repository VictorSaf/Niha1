# Feature 0073 — Introducer contact requests: reconciliere orfani (SSOT users vs `contact_requests`)

## Context

Backoffice tab **Introducer** listează rânduri din **`contact_requests`** cu `request_flow='introducer'`. Ștergerea manuală a utilizatorilor **PREINTRODUCER** / **INTRODUCER** din `users` (maintenance SQL) **nu** șterge automat aceste rânduri, deci lista poate afișa cereri „orfane”. Trebuie reconciliere explicită și documentație SSOT.

## Comportament dorit (implementat)

- **API Admin:** `POST /api/v1/admin/contact-requests/reconcile-introducer-orphans` — răspuns `{ "deleted": <int> }`; șterge `contact_requests` unde `request_flow='introducer'` și **nu** există niciun `users` cu același email (comparare case-insensitive) și `role` în **PREINTRODUCER**, **INTRODUCER**.
- **Serviciu:** `backend/app/services/introducer_contact_cleanup.py` — funcția `reconcile_orphan_introducer_contact_requests(db)` (fără commit în serviciu; endpoint-ul face commit și `handle_database_error`).
- **SQL oglindă:** `scripts/sql/reconcile_introducer_orphan_contact_requests.sql` — același criteriu pentru DBA / medii fără apel API.
- **Client frontend:** `adminApi.reconcileIntroducerOrphanContactRequests()` în `frontend/src/services/api.ts`.
- **Teste:** `backend/tests/test_introducer_contact_cleanup.py` — caz fără user asociat (șters) vs cu user PREINTRODUCER (păstrat).

## Fișiere relevante

- `backend/app/api/v1/admin.py` — router `POST .../reconcile-introducer-orphans`, model răspuns `ReconcileIntroducerOrphansResponse`
- `backend/app/services/introducer_contact_cleanup.py` — logica DELETE cu `NOT EXISTS` pe `users`
- `docs/API.md` — exemplu request/response
- `app_truth.md` — §8 Backoffice default view: sursa listei Introducer + pointer la endpoint și script SQL

## Algoritm (pas cu pas)

1. Construiește un predicat EXISTS: există `users` cu `lower(email) = lower(contact_requests.contact_email)` și `role` în PREINTRODUCER sau INTRODUCER.
2. Șterge din `contact_requests` unde `request_flow = 'introducer'` și predicatul EXISTS este fals.
3. Returnează numărul de rânduri șterse (rowcount).

## Note operaționale

- Rularea pe producție: backup DB, acces admin, același nivel de prudență ca orice DELETE în masă.
- Dacă un `contact_request` există dar crearea userului a eșuat după commit, rândul poate fi eliminat de reconciliere; aplicantul poate retrimite formularul.
